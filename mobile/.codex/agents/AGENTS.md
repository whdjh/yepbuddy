# 에이전트 위임

[프로젝트 지침](../../AGENTS.md)에 더해, 서브에이전트를 사용할 때만 적용한다. 이 Markdown 문서는 에이전트나 모델 설정을 등록하지 않는다.

## 작업 배정

- 목표, 완료 조건, 수정 허용 범위, 필요한 파일 경로·배경, 검증 범위를 전달한다. 구현 직급별 템플릿은 두지 않는다.
- 대화 전체나 긴 소스를 복제하기보다 해당 작업에 필요한 문맥만 제공한다. 이미 전달한 공통 지침을 다시 읽게 하지 않는다.
- 병렬 구현은 수정 파일을 겹치지 않게 배정한다. 공용 파일은 한 담당자가 맡고, 범위를 넓혀야 하면 메인에 이유를 알린다. 다른 담당자나 사용자의 변경을 덮어쓰지 않는다.
- 독립적인 리뷰가 필요할 때 [리뷰 기준](reviewer.md)을 전달한다. 리뷰어는 기본적으로 읽기 전용이며, 커밋 범위나 미커밋 변경 등 실제 검토 대상을 명시한다.

## 모델과 추론

- 비용을 줄이는 기본 선택은 메인 `gpt-6-astra`의 `medium`, 명확한 반복 수정·좁은 탐색은 `gpt-5.6-luna`의 `low`다. 실제 설정은 `config.toml`이나 생성 요청에 지정하며, 명시적인 사용자·세션 설정을 우선한다.
- 저장 데이터 호환성, 네이티브 경계, 복잡한 원인 분석처럼 판단이 어려운 작업은 메인이 맡거나 `gpt-6-astra`와 `high`를 명시해 위임한다. `xhigh`는 해결되지 않은 복잡한 추론에 필요할 때 사용한다.
- 모델·추론 수준을 바꿔 위임할 때는 새 문맥에 필요한 배경만 전달한다. 현재 도구에서 전체 대화 복제가 모델 변경을 지원하지 않으면 작업 설명과 파일 경로를 담은 독립 문맥을 사용한다.
- 동시 하위 작업은 기본적으로 최대 2개로 제한한다. 중복 탐색이나 작은 확인만을 위한 추가 에이전트를 만들지 않는다.

## 결과와 통합

- 담당자는 해결한 동작 또는 발견 사항, 변경 파일, 검증 결과, 남은 문제만 짧게 보고한다. 필요한 정보가 없으면 확인한 근거와 질문을 명시한다.
- 메인은 근거와 통합 diff를 확인하고 완료 조건이 남아 있으면 이어서 처리한다. 통합으로 새 영향이 생겼을 때 필요한 검증을 수행하며, 이미 통과한 검사를 이유 없이 반복하지 않는다.
