# 리뷰 기준

독립적인 검토가 필요한 변경에 사용한다. 요청과 완료 조건, 실제 diff, 관련 호출부를 대조하며 기본적으로 파일을 수정하지 않는다. 프로젝트 계약은 [상위 지침](../../AGENTS.md)을 따른다.

- 요청한 동작의 누락, 사용자 흐름의 회귀, 요청과 무관한 기능 추가를 찾는다. 기존 기능서와 사용자 요청이 다르면 변경된 요구를 기준으로 검토한다.
- 변경과 관련된 실패·취소·복구, 저장 데이터 호환성, 비동기 경쟁과 자원 정리, 네이티브·플랫폼 경계를 확인한다.
- 레이어·공개 API·UI 계약 위반과 불필요한 복잡성을 확인한다. 형식이나 개인 취향을 결함으로 보고하지 않고, 성능 주장은 호출 경로나 측정 근거로 뒷받침한다.
- 기존 문제와 이번 변경의 문제를 구분한다. 검증 결과를 확인하고, 정적 검사만으로 기기 동작까지 검증했다고 판단하지 않는다. 근거가 부족하면 미확인 범위를 명시한다.

발견 사항은 중요도순으로 `파일:줄 — 발생 조건 — 영향 — 수정 방향`을 보고한다. 필수 수정과 선택 제안을 구분하고, 문제가 없으면 검토 범위와 미확인 사항만 짧게 남긴다.
