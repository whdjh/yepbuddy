# 04. 완료 기록·인덱스·메모 편집 정합성

> 상태: 대기
>
> 선행: 없음

## 목표와 범위

완료 기록의 쓰기·수정·삭제를 하나의 저장 경계로 정리하고 결과 화면까지 연결한다. 동시에 갱신해도 값을 잃지 않고 메모 입력 직후 이탈해도 마지막 값이 남아야 한다.

## 작업

- [ ] 완료 parser의 빈 ID·시각 역전·cardio 시각·부위·선택 필드를 검증하고 legacy detail/details를 유지한다.
- [ ] 갱신·삭제를 저장소 내부에서 직렬화하고 그 안에서 최신 본문을 읽어 필요한 필드만 수정한다.
- [ ] 본문 저장·삭제 성공 뒤 날짜 대표 인덱스를 갱신한다. 조회 시 참조 본문의 존재·날짜를 확인하고 stale·누락일 때만 복구한다.
- [ ] 결과 화면 이탈 시 마지막 메모를 같은 저장 경계로 넘긴다. sessionId를 고정하고 삭제 중에는 pending 메모를 다시 저장하지 않는다.
- [ ] 세트 편집 전 메모 저장·저장 잠금·캘린더 삭제 fallback을 유지한다. 숨겨진 저장 실패를 확인·재시도할 수 있게 하고 저장·삭제 액션을 응집된 내부 단위로 정리한다.
- [ ] entity 저장 계약과 결과 기능서를 바뀐 동작에 맞춘다.

## 완료 조건

- [ ] 본문/인덱스 각각 실패, stale 인덱스, 같은 날 두 본문과 대표 삭제에서 유효한 기록을 보존·조회한다.
- [ ] 메모+지표, 세트+캘린더 ID 병렬 변경이 모두 남고 삭제 뒤 늦은 보강이 기록을 되살리지 않는다.
- [ ] 메모 입력 후 0/100/299ms에 버튼·제스처·Android back으로 나가도 마지막 값이 남는다. 저장 실패·세트 편집·삭제 경합도 확인한다.
- [ ] TypeScript·lint와 저장소 동시성·실패 검증이 통과하고 양 플랫폼 결과 편집을 확인한다.
