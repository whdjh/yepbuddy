# 02. 요약·조회·템포의 비동기 상태 복구

> 상태: 대기
>
> 선행: [01](01-code-cleanup.md)

## 목표와 범위

저장·조회·오디오 초기화가 실패하거나 늦게 끝날 때 화면이 잠기고 입력을 잃는 작은 오류들을 고친다. 각 화면의 기존 사용자 흐름을 유지한다.

## 작업

- [ ] 항상 true인 알림 권한 Context와 인자를 없애고 루틴 안내 조건을 유지한다. 안내 수락·종료 안내의 저장 실패 뒤 flag/ref를 복구하고 재시도할 수 있게 한다.
- [ ] 요약 카드의 느린 배치 로드가 사용자 편집을 덮지 않게 하고 저장 실패를 처리한다. 같은 props만 전달하는 row·picker wrapper와 중복 반환값을 줄인다.
- [ ] 목록 더보기 중 active/자정 refresh가 오면 새 요청이 loading·소유권을 함께 초기화하게 한다. 이전 응답이 새 목록을 바꾸지 않게 한다.
- [ ] 운동 route의 추가 URI 디코딩을 없애고 정상 빈 결과와 조회 실패를 구분한다. 편집·삭제 후 화면 갱신과 짧은 필터 목록의 더보기는 재현 결과에 맞춰 보완한다.
- [ ] 템포 화면 이탈 시 대기 중 시작 요청을 취소하고 늦게 생성된 RAF/player를 정리한다. 새로 시작한 요청의 자원은 건드리지 않는다.
- [ ] 실제 바뀐 요약·기록·결과·템포 동작과 프로틴 탭 설명을 관련 기능서에 반영한다.

## 완료 조건

- [ ] 루틴 안내 저장 실패 뒤 다시 시도할 수 있고, 카드 편집 뒤 늦은 로드가 완료돼도 편집이 유지된다.
- [ ] 더보기 지연→refresh→이전 응답 완료 뒤에도 더보기가 가능하다. 정상/손상/없는 ID 링크와 조회 실패에서 렌더 예외가 없다.
- [ ] 템포 초기화가 화면 이탈 뒤 성공·실패해도 RAF/player·소리·햅틱이 남지 않고 재진입·AppState 복귀가 동작한다.
- [ ] TypeScript·lint와 위 실패 경로 검증이 통과하며 변경된 화면을 양 플랫폼에서 확인한다.

진입점: [루틴 안내](../../src/features/view-summary/model/useRoutineCycleFeaturePrompt.ts), [더보기](../../src/features/view-sessions/model/useInfiniteSessions.ts), [운동 route](../../src/app/workout/[id].tsx), [템포](../../src/features/use-tempo/lib/useTempoTimer.ts).
