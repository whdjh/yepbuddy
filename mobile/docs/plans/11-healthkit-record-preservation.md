# 11. HealthKit 운동 기록 보존과 기존 이력 전환

> 상태: 대기
>
> 선행: [10](10-icloud-settings-backup.md)

## 목표와 범위

완료 운동과 검증된 앱 고유 정보를 HealthKit에 보존하고 세트·메모 수정·기록 삭제까지 일관되게 반영한다. 기존 로컬 이력도 원본을 유지한 채 전환해 재설치 후 조회할 수 있게 한다.

로컬 운동 저장이 우선이며 건강 접근 거부·저장 실패·미지원 상태가 운동 기록을 막지 않아야 한다. 로그인·자체 백업 서버를 추가하지 않고 개인 건강정보를 앱 전용 iCloud 파일이나 CloudKit에 복제하지 않는다.

[10번의 데이터별 계약](./10-icloud-settings-backup.md)에서 확인한 필드·저장 위치·API만 사용한다. 메타데이터는 운동에 부속된 정보이며 일반 설정이나 임의 데이터를 넣는 백업 공간이 아니다. 루틴·위치·장소 삭제 선택의 미확정 보존 경로를 임의로 구현하지 않는다.

| 경로 | 이 PR에서 보장할 결과 |
| --- | --- |
| 새 운동 완료 | 미리 정한 세션 ID로 로컬·건강 운동을 연결하고 실패 시 재시도 |
| 세트·메모 수정 | 검증된 API로 보존 정보에 반영하고 UUID·심박수 연결 유지 |
| 기록 삭제 | 삭제 의도가 재시도·예전 기기 재연결 뒤에도 유지 |
| 이미 연결된 기존 기록 | 필요한 정보만 보강하고 원본·심박수 관계·중복 방지 확인 |
| HealthKit 미연결 기록 | 실제 출처·건강 저장 권한에 맞게 보존하고 실패한 원본 유지 |
| 원본도 사라진 옛 기록 | 없는 메모·세트·부위·생체값을 과거의 실제 값처럼 생성하지 않음 |

자동 로컬 복원·인덱스 재구성·설정 상태 화면은 [12번](./12-iphone-auto-restore.md)에서 연결한다. 이 PR은 보존한 새 운동의 이후 수정·삭제와 기존 사용자 전환까지 동작하는 상태로 반영한다.

## 작업

- [ ] 완료 전에 로컬 세션 ID를 정하고 건강 운동의 소유권·버전·revision·메타데이터를 연결한다. 옙버디 소유 운동만 식별하며 다른 앱 운동을 가져오거나 변경하지 않는다.
- [ ] 로컬 완료 저장 뒤 HealthKit 보존과 성공·실패·재시도 상태를 연결한다. 기존 완료 후처리와 저장 경로가 중복 운동을 만들지 않게 한다.
- [ ] 세트·메모 및 허용된 운동 정보의 수정에 검증된 API를 적용한다. 저장된 HealthKit 객체를 임의 변경할 수 있다고 가정하지 않고 저장 순서·UUID 변경·심박수 연관 관계를 처리한다.
- [ ] 기록 삭제·revision·충돌 처리를 연결해 중단·재시도·구형 기기 재연결 후 수정이 역행하거나 삭제한 기록이 부활하지 않게 한다.
- [ ] 같은 세션의 반복 저장·재조회·재시도를 멱등하게 처리한다. 실패·거부·미지원 기록은 로컬에 남기고 외부 보존 완료로 표시하지 않는다.
- [ ] 기존 로컬 세션을 스캔해 건강 운동 연결·메타데이터 보존 여부·출처·누락 필드를 구분한다. 로컬 원본을 먼저 지우지 않는다.
- [ ] 연결된 기존 운동은 허용된 보강 방식으로 전환하고, 미연결 운동은 출처·권한에 맞게 보존한다. 전환 중 새 운동·수정·삭제와 기존 UUID·심박수 관계를 보존한다.
- [ ] 전환 진행 상태와 실패 재시도를 관리해 반복 실행·앱 중단 후에도 중복이 생기지 않게 한다. 계정 변경 시 이전 계정에서 유래한 데이터와 대기 쓰기를 분리한다.
- [ ] 메타데이터 없는 옛 운동·심박수 없는 기록·복구 불가능한 필드를 구분하고, 저장·수정·삭제·전환 후 재설치 조회 결과를 필드별로 기록한다.

## 완료 조건

- [ ] 메타데이터의 정상·누락·손상·구버전·미지원 버전, 소유권·세션 식별과 반복 저장·수정·삭제·전환 재시도 검증이 통과한다.
- [ ] HealthKit 실패·거부·미지원 상태에서도 로컬 완료 기록이 유효하며, 전환 실패로 기존 원본·새 기록·수정·삭제 의도를 잃지 않는다.
- [ ] 실제 iPhone에서 신규 저장·수정·삭제와 기존 연결/미연결 기록 전환을 수행하고 값·중복·UUID·심박수 연관 관계를 비교한다.
- [ ] 전환 후 실제 앱 삭제·재설치 조회로 보존 필드를 확인한다. 메타데이터 없는 옛 운동·심박수 없는 운동과 복구 불가능한 값은 별도로 기록한다.
- [ ] 구형 상태의 재시도·기존 기기 재연결로 수정이 되돌아가거나 삭제 기록이 부활하지 않으며 다른 앱 운동이나 다른 계정에 영향을 주지 않는다.
- [ ] 개발·TestFlight/배포 구성의 HealthKit entitlement와 native build를 확인하고 로컬 저장·Apple 건강 동기화·미확인 조건을 구분한다.
- [ ] `bunx tsc --noEmit --pretty false`, `bun run lint`가 통과한다. Workout plugin 변경은 `node scripts/check_workout_session_plugin.cjs`, widget 변경은 `node scripts/check_dynamic_island_widget.js`로 검증한다.

## 근거와 주의점

- [완료 저장소](../../src/entities/workout-session/model/storedWorkoutSessionStorage.ts)는 로컬 세션·날짜 인덱스를 관리한다. 외부 보존을 위해 기존 키·포맷을 임의 변경하지 않는다.
- [세션 타입](../../src/entities/workout-session/model/types.ts)과 [HealthKit API](../../src/entities/workout-session/api/healthKit.ts)를 대조해 로컬 필드·건강 운동 연결·현재 저장 경로를 확인한다.
- [네이티브 완료 처리](../../plugins/ios/workout-session/LiveWorkoutSessionController.swift)의 `finishWorkout`과 기존 경로에서 저장하는 시작·종료·종류·에너지를 함께 확인한다.
- [상세 조회 조합](../../src/entities/workout-session/lib/sessionHealthKitData.ts)은 기존 HealthKit UUID를 사용한다. 보강 과정의 UUID 변경이나 심박수 연결 손실은 상세 조회 회귀로 검증한다.

[HealthKit Metadata Keys](https://developer.apple.com/documentation/healthkit/metadata-keys)의 기술 지원만으로 모든 필드의 수정 방법이나 심사 허용을 확정하지 않는다. 데이터별 보존 제한과 공식 근거는 [10번 계획](./10-icloud-settings-backup.md)의 계약을 따른다.

[건강 앱 개인정보 안내](https://www.apple.com/legal/privacy/data/en/health-app/)의 동기화는 OS가 담당한다. HealthKit 로컬 저장 성공만으로 다른 기기까지 동기화됐다고 표시하지 않는다.

건강 동기화 비활성화·권한 미허용·오프라인·사용자 건강 데이터 삭제와 아직 보존되지 않은 로컬 기록은 재설치 복원을 제한한다. 옛 건강 기록에 값이 없고 로컬 원본도 사라졌다면 임의 기본값으로 복구하지 않는다.

구현·기기 검증이 끝나기 전에는 보존 기능을 완료로 처리하지 않는다. 이 PR의 재설치 조회 성공과 12번의 전체 자동 복원 성공은 구분한다.
